# LemLib — the Lean 4 runtime for Lem-generated code

**Checked 2026-09-25:** implementation `fd048dbaeed9e0031496aa6ae4a56bb20c07841a`.

Code generated by `lem -lean` imports this library: the `LemOrdering`
comparison type, comparator-keyed set/finite-map operations, numeric
and string bridges, and the supply-threading split (`supplySplit` — a
plain def; the library declares ZERO axioms, and the backend adds none.
Raw target text and downstream imports need their own axiom audit; see the module docstring and the no-axiom note at the top of
`LemLib.lean`).

Generate its library modules first with `make lean-libs` at the repository
root. Build: `../scripts/capped lake build` from this directory
(toolchain per `lean-toolchain`). Property tests:
`LemLibTest.lean`. Kernel-checked theorems: `LemLibTheorems.lean` (the
tail-recursive rewrites equal the definitions they replaced; the
height-indexed `join` equals the well-founded one under `heightsOk`) and
`LemLibPmapLaws.lean` (lookup-after-insert laws for `Pmap`/`Fmap` under a
strict-weak-order comparator: `Pmap.WF`, `Pmap.find?_add_same`,
`Pmap.find?_add_other`, the `Fmap` corollaries) — every theorem closed
under `propext`/`Classical.choice`/`Quot.sound` at most, `#print axioms`
at the end of each file.

Documentation for the backend that targets this library:
[`doc/lean-backend/README.md`](../doc/lean-backend/README.md).

Pset/Pmap are translations of OCaml AVL algorithms, with local laws and
finite tests; no general OCaml–Lean equivalence theorem is supplied.
Strings use Unicode scalars rather than OCaml bytes. The parity suite has
eleven registered expected failures in three classes (a planned fix, a
ruled OCaml-target deviation, an open discrepancy; the register is
`tests/comprehensive/parity/expected_failures.txt`, described in the
backend DESIGN). Native clients that require reached
panics to stop execution must set `LEAN_ABORT_ON_PANIC=1`; unused pure
failures can still be erased. General fuel propagation is not proved.

The translated Pset/Pmap portions retain the OCaml source attribution and
license terms. Read [NOTICE.md](NOTICE.md) and [LICENSE](../LICENSE);
do not describe the entire runtime as BSD-only.

The `fuelExhausted` wrapper, like its opaque primitive, is marked
`never_extract`: this keeps a closed sentinel in its branch instead of
allowing native extraction to evaluate it during module initialization.
The `p_lem_size` parity probe exercises the sufficient-fuel path with
`LEAN_ABORT_ON_PANIC=1`; general fuel propagation still requires proofs.
